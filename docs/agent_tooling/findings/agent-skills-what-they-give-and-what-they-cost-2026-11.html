Aussage

  1. What it is. A skill is a folder with SKILL.md and optional scripts/, references/, assets/. The header has two required fields: name (at most 64 characters, lower case, digits, hyphens, equal to the folder name) and description (at most 1,024 characters: what it does and when to use it) [1].
  2. Three loading levels. Name and description of every skill at the start of a session (about 100 tokens each); the body when a task matches (recommended under 5,000 tokens and under 500 lines); scripts and reference files only when a step needs them, and a script is run, not read [1][2][3].
  3. One format for many agents. Introduced in October 2025 [2], an open standard since, given to the Agentic AI Foundation on 2026-10-22; more than 70 agent platforms read it [5]. On one workstation here, Claude Code [4], Hermes [8] and Codex or OpenCode [7] read the same folders.
  4. Measured gain, with conditions. SkillsBench, version 4: 87 tasks in 8 domains, 18 model and harness configurations, average pass rate 33.9 % without and 50.5 % with curated skills; focused skills with at most 3 modules beat larger bundles. Version 1 (86 tasks, 7 configurations): skills written by the models themselves gave no benefit on average [12].
  5. Risks of foreign skills. Pattern scan of 31,132 public skills: 26.1 % with at least one vulnerability pattern (patterns, not confirmed attacks) [9]. 98,380 skills examined, 157 confirmed malicious [10]. Instructions hidden in skill files succeeded in up to 80 % of attempts against frontier models [11]. Consequence here: write skills ourselves; read a foreign skill and its scripts before installing.
  6. A skill is advice, not a lock. What must hold every time belongs in a hook or in the tool itself [4].
  7. Own comparison with and without a skill (skill film-making, 2026-11-24, one run per cell): both sides passed all checkable statements in both cases (9 of 9, 8 of 8). In the build case the run with the skill used 123,452 instead of 159,879 tokens and 21 instead of 36 tool calls; in the planning case it saved nothing (134,812 against 129,940 tokens). The agent without the skill found the same rules in an older skill, this wiki and 15 to 18 memory notes. On a workstation with a full memory the gain of a skill is therefore one short, testable place and the same rules for agents without that memory, not more correct results.
  8. Own trigger test. Ten fresh sessions, one request each, ending with "first tell me your plan in 5 lines", only the skill tool offered. With the first descriptions, 3 of 7 matching requests loaded the skill (film 2 of 4, overlay 1 of 3; two of the four misses named the skill or its content in the plan without opening it), 3 of 3 near misses stayed away. After adding one sentence to each description ("Load it before planning or touching such work ..."), 7 of 7 loaded and 3 of 3 near misses still stayed away.
  9. Own count of one home-built agent loader. It kept the first 200 characters of a description and read the header line by line: of 19 linked skills, 12 descriptions were cut, 2 showed only ">" (a description that continues on the next line), 5 were complete; 11 of 30 existing skills were not linked. A skill can be installed and still be invisible. Not repaired on the day of the count.
  10. Where a rule belongs. For every session: the always-loaded instruction file, kept short. Know-how for one kind of task: a skill. Never to be broken: a hook or the tool. The one-off part of a task (goal, data, how we see that it is finished) stays in the prompt; no skill can know it.

Trägt nicht

Sources 9 to 12 are preprints without peer review; only abstracts and version notes were read, not the full papers. The own comparison has one run per cell and one skill; the trigger test has one run per request and asks for a plan only, which is harder than a real task in which the skill can still load when the work starts. Nothing was tested with agents other than Claude Code. Claims that could not be confirmed were left out (for example a count of "341 malicious skills" that circulates without a source that could be opened).

Bruchindikator

A repeat with several runs per cell shows no saving in the build case; a later version of an agent loads skills without regard to the description; the format changes its header fields.

Ablesung

Before writing a skill: is the work recurring, and is there a script-shaped part? Write the description as what + when + when not, with the words the user really types, and add "load it before planning". Keep the body short, put fixed steps into scripts, write 2 to 3 eval cases, run them with and without the skill, and test the description with a few fresh requests and near misses.
