Volumetrie des Gehirns ueber die Zeit (SynthSeg, FreeSurfer, eigene Netze): wie Verlaufszahlen gerechnet und wie ihre Messfehler ausgewiesen werden. Keine Patientendaten; Zahlen bleiben bei den Projekten.

Stand 2026-10-12. Ein Eintrag je Datei.

Kurzstand

Stand 2026-10-12. Prefill fuer Chats und Agenten. Details in INDEX.md.

Verlaufs-Volumetrie liefert zwei Seiten: die Trendseite (gemischtes Modell, Steigung je Proband, Seitenvergleich) und die Fehlerseite. Die Fehlerseite hat vier Bausteine: Test-Retest je Struktur aus zwei Segmentierungen derselben Sitzung (SDw, CV, ICC(2,1), SDC95 = 1,96 * sqrt 2 * SDw, Bland-Altman), Laengsschnitt-Residuen und kuerzestes Intervall, Nachweisbarkeit (Jahre bis eine Person die SDC ueberschreitet, KI in denselben Einheiten), Ausfall/QC je Zeitpunkt. Laesionsausschluss nur, wenn die Maske in allen Sitzungen existiert, sonst entstehen Maskeneffekte von +1400 %.

Lesen bei: Volumetrie, SynthSeg, FreeSurfer, Atrophie, Verlauf, Laengsschnitt, Test-Retest, SDC, ICC, Messfehler, Hippocampus.

Neu 2026-10-12: SynthSeg in FreeSurfer 8.2 rechnet nur auf CPU (85 s je Sitzung mit --robust); Vollkohorten in Ordner-Batches, 3 parallel. Nach jeder Kohortenkopie gzip -t ueber alle NIfTI (eine abgeschnittene T1 lag 5 Wochen unbemerkt). Rechenplan-Literatur: FreeSurfer longitudinal stream (Reuter 2012) und Euler-Zahl als QC-Gate (Rosen 2018) sind die belegten Hebel; FastSurfer-Dicke ICC 0,92 vs 0,87.

Regel (2)

RegelAfter copying a cohort, run `gzip -t` over every NIfTI and compare file counts and byte totals with the sourcegetragen2026-10-12nach jeder Kohortenkopie gzip -t ueber alle NIfTI, Dateizahl und Bytes gegen die Quelle; du auf exFAT luegt

Herkunft: DEMDAS pilot, 12.10.2026: one T1w was a truncated copy (508 KB of 5.2 MB) since 03.09. · eigene Seite · Markdown

Aussage

A truncated .nii.gz is silent until a tool reads past the cut: in the DEMDAS pilot one T1w (508 KB instead of 5.2 MB) sat in the BIDS tree for five weeks; SynthSeg failed with zlib.error: invalid distance code deep in a log, the session simply vanished from the QC page ("31 of 63"), and recon-all would have failed the same way. The sweep is cheap: 886 NIfTI (12 GB) in under two minutes. For a cohort copy, also compare file count and summed bytes of source and target, and run an rsync -c dry run; du -sh is useless on exFAT (cluster inflation: 67 GB shown for 43.7 GB of data).

Traegt

Every copy of imaging data from USB drives, network shares or sticks; the inventory step of a new cohort.

Traegt nicht

Uncompressed files; corruption inside a valid gzip stream (that needs a hash from the source).

Bruchindikator

A session missing from a QC page without a stated reason; a .nii.gz far smaller than its siblings.

Ablesung

12.10.2026 16:16-16:25 (gzip sweep, inventory size 5.221 MB vs local 508 KB, replacement from the external SSD).

RegelJede Verlaufs-Volumetrie bekommt eine Fehlerstatistik neben der Trendstatistikgetragen2026-10-12Zu jeder Trendseite eine Fehlerseite: Test-Retest (SDw, CV, ICC, SDC95, Bland-Altman), Laengsschnitt-Residuen, Nachweisbarkeit (Jahre bis SDC), Ausfall/QC je Zeitpunkt; Laesionsausschluss nur mit Maske in allen Sitzungen

Herkunft: Nutzer 12.10.2026 zum DEMDAS-GM-Beispiel: "bei DEMDAS muss man auch die Fehlerstatistiken rechnen"; umgesetzt in demdas-gm/fehler_statistik.py · eigene Seite · Markdown

Aussage

Eine Seite mit jaehrlichen Aenderungen (gemischtes Modell, Steigungen je Proband) ist ohne Messfehler nicht lesbar: niemand kann sehen, ob -0,8 %/Jahr Amygdala mehr ist als das Rauschen. Deshalb gehoert zu jeder Verlaufs-Volumetrie eine zweite Seite error_statistics.html mit vier Bausteinen, alle ohne neue Bildrechnung, wenn die Daten da sind:

  1. Test-Retest je Struktur aus zwei Segmentierungen derselben Sitzung (hier: MPRAGE ohne und mit Verzeichnungskorrektur, beide SynthSeg). Kennzahlen: Mittel, Bias, SD der Differenz, Within-Subject-SD = SD/sqrt 2, CV %, ICC(2,1), SDC95 = 1,96 * sqrt 2 * SDw (kleinste Aenderung, die bei EINER Person als echt gelten darf), Bland-Altman-Plots. Ehrlich kennzeichnen, wenn das Paar kein echtes Scan-Rescan ist: dann ist es eine obere Schranke.
  2. Laengsschnitt-Rauschen aus der Pipeline selbst: Residuen-SD um die Gerade je Proband (>= 3 Sitzungen, % der Baseline) und die Aenderung ueber das kuerzeste Intervall (M0 -> M6) als Verteilung. Enthaelt Biologie + Fehler, sagt das auch.
  3. Nachweisbarkeit: jaehrliche Aenderung (gemischtes Modell, mit KI in denselben Einheiten!) gegen SDC95 -> Jahre, bis eine Einzelperson die SDC ueberschreitet. Ein Balkenbild mit beiden Groessen je Struktur.
  4. Ausfall- und QC-Zaehlung je Zeitpunkt: Sitzungen, Segmentierungs-QC unter Schwelle, fehlende Laesionsmasken, Ausrichtungs-Dice, recon-all fertig/abgebrochen, Zusatzgroessen (WMH) vorhanden.

Nebenregel aus dem ersten Lauf: relative Aenderungen mit Laesionsausschluss nur, wenn die Maske in allen Sitzungen existiert. Fehlt sie in Folgesitzungen, werden aus einem fast weggemaskten M0-Wert Aenderungen von +1400 % -- ein Maskeneffekt, der in jeder Verlaufszahl steckt, bis die chronische Maske da ist.

Traegt

Jede Verlaufs-Volumetrie (SynthSeg, FreeSurfer, eigene Netze) auf dem Stick oder fuer Dritte; die Deutung jeder Steigung; die Entscheidung, ob ein Laengsschnitt-Strom (FreeSurfer longitudinal) noetig ist (ja, wenn Jahre bis SDC > Studiendauer).

Traegt nicht

Querschnittsvergleiche zwischen Gruppen (dort zaehlt die Gruppen-SD, nicht die SDC); Datensaetze ohne zweite Segmentierung je Sitzung -- dann bleibt nur Baustein 2 bis 4 und die Literatur-SDC.

Bruchindikator

Eine Trendseite ohne Verweis auf die Fehlerseite; eine Nachweisbarkeitstabelle, deren KI in anderen Einheiten steht als die Punktschaetzung (im ersten Lauf passiert: %ICV/Jahr neben relativ %/Jahr).

Befund (1)

BefundSynthSeg inside FreeSurfer 8.2 runs on the CPU only; plan 85 s per session with --robustgetragen2026-10-12fspython TF 2.13 ohne GPU; 85 s je Sitzung mit --robust, Ordner-Batches laden das Modell einmal; recon-all 8.2 40-48 min

Herkunft: DEMDAS full cohort compute planning, 12.10.2026 (Alita) · eigene Seite · Markdown

Aussage

mri_synthseg in FreeSurfer 8.2.0 uses the bundled fspython with TensorFlow 2.13.1 built WITHOUT GPU support (tf.config.list_physical_devices('GPU') returns [] on a machine with a working CUDA 12.4 torch). Measured on a 24-core workstation: --parc --robust --cpu --threads 6 takes about 85 s per 1 mm MPRAGE, plus about 20 s model load per call. Running batches of 40 images as a folder (--i <folder> --o <folder>) loads the model once per batch. Three batches in parallel (about 10 GB RAM each) give about 1652 sessions in 13-15 h on one workstation, with no GPU needed, so a local LLM can keep the GPU. FreeSurfer 8.2 recon-all -all measured 40-48 min per session with -openmp 4, 3 in parallel, peak RAM 17-28 GB per run (mri_synthseg / mri_synthmorph stages); the literature figure of 4-7 h per recon-all is for FreeSurfer 6/7.

Traegt

Compute plans for cohorts of 1000+ sessions on single workstations; the choice between SynthSeg-in-FreeSurfer and a standalone SynthSeg/FastSurfer with GPU; the decision not to stop a local LLM server for a SynthSeg batch.

Traegt nicht

Standalone SynthSeg (own TensorFlow with CUDA) and FastSurfer (PyTorch) -- both use the GPU; FreeSurfer versions other than 8.2.0.

Bruchindikator

A FreeSurfer release whose fspython lists a GPU, or a measured --robust time far from 85 s on comparable hardware.

Ablesung

12.10.2026 16:36 fspython TF check; 16:29 Clara's 2-session ND test (85 s each); 16:40 one-image smoke test of the batch script (71 s incl. load); recon-all times from alle.log 12.10. (5 sessions, 40-48 min).
