Lademodus bei Expert-Offloading: mmap oder none?

TypPrüfpunktStatusoffenStand2026-08-29HerkunftProjekt local_models, Victus, 2026-08-29Zuletzt geändert2026-10-02 Add local_llm_operation topic: measured operation of a local MoE modelVerweist aufEin MoE-Modell laeuft auf einer GPU, auf die es nicht passt (local_llm_operation)Quelleknowledge/local_llm_operation/open_checks/mmap-vs-load-mode-none.md

Aussage

llama-server warnt beim Start mit -ncmoe:

tensor overrides to CPU are used with mmap enabled
 - consider using --load-mode none for better performance

Die eigene Doku in local_models/docs/02-tuning.md empfiehlt dagegen mmap, begruendet mit SSD-Schonung: Verschleiss entsteht durch Schreiben, nicht durch Lesen. Unter -lm none liegt das Modell in anonymem Speicher und landet bei RAM-Mangel im Pagefile - echte Schreibvorgaenge.

Beide Seiten haben ein Argument. Keine der beiden ist gemessen.

Traegt

Nichts. Das ist der Punkt des Eintrags.

Traegt nicht

Die aktuelle Empfehlung mmap ist eine Vermutung, kein Befund. Wer sie zitiert, zitiert eine Vermutung.

Bruchindikator

entfaellt

Ablesung

blind

Zu messen

Beide Modi auf derselben Maschine, gleicher -ncmoe, gleicher Prompt: Prefill und Decode getrennt (siehe [separate-prefill-from-decode]), dazu freier RAM und Pagefile-Schreibrate waehrend des Laufs. Entscheidend ist der Fall mit wenig freiem RAM - bei viel freiem RAM duerften sich beide Modi kaum unterscheiden.

Auf Victus waren waehrend des Betriebs 1,5 GB frei, das ist der interessante Fall.
