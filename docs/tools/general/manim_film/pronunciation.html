The text-to-speech voice reads technical words badly. Write the spoken text (beats/*_beats.json) the way it should sound; the words drawn on screen keep the real spelling. Rule from the user (2026-11-06): if you are not sure how a hard word should sound, ask before rendering, and add the answer here.

Note on letter-by-letter words (2026-11-06): the user wanted "P G P U" a little faster. Kokoro (af_heart) pauses at spaced letters and reads a spaced or hyphenated "A G P U" / "A-G-P-U" as the article "uh" + GPU. Uppercase "PGPU" / "AGPU" is spoken letter by letter like "CPU" and was the shortest (13.80 s against 14.08 s spaced, 13.90 s hyphenated, same sentence; phonemes checked with the Kokoro G2P output). So: write short letter acronyms in capitals without spaces.

Machine-readable list and check (2026-11-09)

pronounce.json is the same table for the tools: voice.py applies it before speaking, and src/say_check.py <film> lists the words to hear and makes a listening file. Keep both files in step.

How to use it

  1. Before the voice step, search the spoken text for capitals, digits mixed with letters, command names and dots (grep -E '[A-Z]{3,}|[a-z]+[0-9]|\.sh|--').
  2. Replace each hit with the spoken form from the tables. Anything not in the tables: ask the user, then add it here.
  3. Only the changed beats need a new voice; the engine skips unchanged text.

Sources: user decisions in the sessions of 2026-11-04 and 2026-11-06 (Clé/Bianca films, HPC tutorial film).
