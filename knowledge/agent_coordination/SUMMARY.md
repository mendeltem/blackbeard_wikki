# agent_coordination: Kurzstand

2026-10-22 (6): **Wachen fragen nach der Rolle, nicht nach dem Einhängepunkt.** Die pauschale Sperre des Wechselmedien-Pfads war ein Ortsmerkmal, kein Inhaltsmerkmal -- derselbe Träger trug auch ~74 GB Werkzeug. Jetzt entscheidet eine Rollendatei `ARBEITSPLATTE` im Datenträgerwurzelverzeichnis; fehlt sie, gilt der Ort weiter als Ablage. Die Regel wird dadurch strenger (jeder nicht erklärte Datenträger ist verdächtig) und die Inhaltsprüfungen bleiben unverändert scharf. Zwei Fallen: Umgebungsvariablen sind additiv und ersetzen nie, und Trägernamen mit Leerzeichen zerlegt man nicht am Wort.

2026-10-22 (5): **Derived artifacts carry the class of their source, and redaction does not lift it.** A KV cache is processed prompt state in number form -- a copy, not a summary. Three older caches belonged to themes the guard blocks as cohort-bearing; nothing readable is inside them, so no content scan would have caught it. They were excluded from the export by rule, and the same rule excluded all 19 fresh caches. The speed claim was measured too and is weak: cold prefix 4.4 s, warm 0.4 s, after a distractor 0.8 s, against 29-34 s of process startup -- so 21 GB bought almost nothing. Data-free source files only go to the group drive. Details in [findings/derived-artifacts-carry-their-source-class.md](findings/derived-artifacts-carry-their-source-class.md).

2026-10-21 (4): **/tmp on Alita is not volatile.** It sits on the root filesystem (`/dev/nvme0n1p2`, ext4), `tmp.mount` is not-found, and Claude Code keeps ~13 GB in ~59,000 files under `/tmp/claude-1000` with no `TMPDIR` set, so nothing ages out. Cleanup is only safe when no agent session runs (`lsof +D` first; 8 claude processes and 2 guard daemons were active here); better than deleting is pointing `TMPDIR` at `/run/user/$UID` so scratch dies with the process. Details in [findings/tmp-is-not-volatile-and-session-stores-persist.md](findings/tmp-is-not-volatile-and-session-stores-persist.md).

2026-10-21 (3): two rules added. **A no-AI clause binds locally too** - if an agreement forbids AI processing, it forbids the local model and the institutional machine as well; following it costs almost nothing, ignoring it risks the whole access, and local execution is a route, not an exception. A dataset with such a clause has no usable class here: read the agreement first, assign the class second. **Do not log case-level content** - a log is a copy, and if it must not be committed it must not be logged either; counts and decisions yes, ids, paths, values and image headers no; intermediate state belongs in the run's own temporary space, not next to the data and not in a persistent session store.

2026-10-21 (2): the class rule now carries the two things it was missing. **Inheritance:** an artefact carries the maximum class of its inputs - a mask, an embedding, a log line, a QC page or a model trained on class-3 data is itself class 3. **Persons, not buildings:** inside the institution, patient data access is role-bound (GDPR Art. 9(3)), so "class 2 may run here" is only as good as the name attached to here. Class 2 is also the softest class and must be read per agreement: DUO `IS` (institution specific) fits it, DUO `NMDS` (no methods research) forbids the software development our own rule assumes. Compared against established practice, the nearest counterpart is the Turing Data Safe Haven tiers 0-4; it judges by harm and pseudonymisation, this scheme judges by route, and established TREs additionally check the *output* where class 2 does not. Enforcement is weaker than it looks: `no_proxy` contains `.charite.de`, so a proxy log never sees the institutional route, and `netzsperre.sh` says of itself that it never ran on this machine. The guard needs a reject-pass-reject self-test with a mutation probe, not a rejection count. Details in [INDEX.md](INDEX.md).

2026-10-21: three headless Claude research passes invented two PMIDs for real-looking claims (one resolved to a surgical-residency paper, one to an inner-ear gene transfer paper). Every identifier from a research pass is a claim to check, not a lookup already done - see [findings/research-passes-invent-plausible-pmids.md](findings/research-passes-invent-plausible-pmids.md).

2026-10-21: data classes are now a main rule in this area. Class 1 fully open (public GitHub, any cloud, any model), class 2 institution-usable under a data use agreement (Charite-internal hub only, e.g. HCP-Aging whose terms allow institutional sharing), class 3 own patient data (local profile only). The class is looked up per dataset before any agent touches it and applies to every wiki area.
