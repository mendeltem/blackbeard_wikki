# agent_tooling: Kurzstand

**New 2026-11-24 (own review, reading only):** All 39 skills of one workstation read against seven points: 1 good, 18 usable, 15 "needs work", 5 outdated. Every skill kept the size limits of the format; the weak points were outdated content (32 skills), unclear or dead instructions (30) and overlap (26). Causes: the agent program and the sandbox changed, the skills did not; twin skills drifted apart. See point 11 of [Agent Skills](findings/agent-skills-what-they-give-and-what-they-cost-2026-11.md).

**New 2026-11-24 (research + own test):** Agent Skills (a folder with `SKILL.md`, read by more than 70 agent platforms) cost about 100 tokens each until a task matches. A benchmark preprint reports 33.9 % to 50.5 % pass rate with curated skills, none on average for self-written ones, and small focused skills beating bundles; three preprints show that foreign skills are an attack path. Own test: a film skill did not change correctness for an agent with a full memory, saved about a fifth of the tokens in a build task and nothing in a planning task; skills loaded before planning in 3 of 7 matching requests with the first descriptions and in 7 of 7 after one added sentence. Two skills are in `tools/skills`. Explanation films are now always animated in Python and their length follows the complexity ([agent-skills-what-they-give-and-what-they-cost-2026-11](findings/agent-skills-what-they-give-and-what-they-cost-2026-11.md), [explanation-video-is-the-standard](rules/explanation-video-is-the-standard.md)).

**New 2026-11-22 (own build, live):** A public prompt-writing trainer (mendeltem.github.io/Prompt_trainer) makes its quiz questions from 42 complete model prompts by changing exactly one part (nine kinds of flaw, five question types, over 1000 items, each combination checked by program), explains every option and counts the first try, as the feedback research suggests. Because a multiple-choice scenario samples judgement and not writing, it has a writing mode with rough browser hints, a self-check and a model answer. No validated performance test of prompt skill was found; published scales are self-reports. Not yet measured: whether quiz scores predict better written prompts. [Entry](findings/prompt-skill-practice-quiz-from-single-flaw-items.md)

**New 2026-11-22 (pointer, nothing run):** MAVE (Chang et al., 2026, arXiv:2611.22464) rebuilds a film shot as an editable Blender scene: measure cameras, people and geometry first, let an agent build inside these constraints, check every step by program. The authors report gains of 27.5 to 41.1 points on their own benchmark of 50 shots; on 2026-11-22 the code is announced but not released and has no licence. Entry: mave-editable-3d-blockouts-from-film-shots.

**New 2026-11-21 (own read-out):** Three weeks of logs of one agent workstation: request errors through the relay fell from 27 % (first 7 days) to 0.6 % (last 7 days, under low load), the crash loops and memory kills did not come back, 91 % of work sessions ran to the end. Still open: the system disk is at 0.7 % free, 6.4 of 8.4 warning lines per hourly check repeat old states, five faults stayed open for 7 to 13 nights, a test that did not run raised no alarm, and the hub does not report whether it reuses input. Eight proposals in order, eight charts, published figures with a note on which of them compare ([entry](findings/agent-station-reliability-trend-2026-11.md)). **Update the same evening:** seven of the eight proposals are built (disk at 73 GB free, each warning once, a smoke test after a repair, tests that did not run in red, a repair list with a deadline, network noise apart); a timing test shows that the hub reuses the start of a prompt (0.7 s against 1.3 s at 12,000 input tokens) without reporting it. Correction: the chat test was missing on 12 of 14 mornings, not 7, and the weekly deep test never ran.

**New 2026-11-20 (own scan):** A log that a code comment calls free of text carried file names and id-like strings in its reasons field (about 1 line in 10); a claim like that is measured by counting pattern hits per field, and a hit is checked before it is reported (55 "keys" were web addresses). Instead of a new shared log, a daily note with counts from the existing logs goes into the agent's recall; reasons are counted by their fixed first phrase and the writer refuses when its own note fails the privacy check. Follow-up to the memory rewrite: a rule-based cut of the oldest step blocks cured the one section it was written for (page took in 37 entries), 2 of 3 real updates were still rejected for other sections. See `findings/log-without-text-is-a-claim-to-measure-daily-counts-instead-of-a-new-log.md`.

**New 2026-11-20 (own check):** A full check of a running agent system found seven faults that the nightly reports had named for up to 8 days; a report without a build decision repairs nothing, and the watcher itself read a wrong log path. Rewriting a long memory page one section per call works for pages with room, but a section far over its budget is not shortened by the model (1 of 3 real runs passed); a guard must count the source pointers a draft keeps (one section lost 59 of 74 without it). See `findings/agent-system-check-nightly-reports-need-a-build-loop.md`.

**New 2026-11-02 (error catalogue):** 88 incidents since September, only 8 surfaced as crashes; 11 kinds came back although a written rule existed. Five root causes (silent fallbacks, acceptance checking files not content, waiting read as running, resources without an owner, operator habits). Each repeated rule became a check: enqueue smoke test, progress watchdog with fallback counter, plausibility in acceptance, restart back-off, hub retries, a pre-command hook.

**New 2026-10-31:** An idle interactive agent session held the GPU queue for 15 h because "any agent process" counted as active; interactive sessions now count only while their session log grows ([idle-interactive-agent-blocks-the-gpu-queue](risks/idle-interactive-agent-blocks-the-gpu-queue.md)). Werkzeuge, auf deren Ausgabe sich jemand verlässt. Roter Faden: Ein Prüfwerkzeug, dessen eigener Fehler wie ein Befund aussieht, ist das gefährlichste.

**Getragen (alles Regeln):** Kein stiller Rückfallwert. Leer ist nicht fehlend. Unbekannt ist kein Wert in Vergleichen (`null <= 0` ist wahr). Erstmessung ist keine Veränderung. Gerechnetes und Gedeutetes getrennt halten (zwei Schichten).

**Vorschlag (aus dem Projekt rea übernommen):** Werkzeuge nach Aufgabenform schneiden (inspect, search, trace, compare, workflow, observe), Primitive vor Workflows, vollständige Ergebnisse, Belege inline, keine Bestätigungs-Schalter. Ob ein Agent das richtige Werkzeug wählt, zeigt nur eine Spur am echten Host, nicht Schema oder Wortüberlappung. Skills routen zuerst nach Zielart und gehen vor dem Abschluss ihre Checkliste durch. Tests belegen Aussagen (echter E2E vor Integration vor Goldens), nicht Verkabelung; verweigerte Berechtigung ist kein Bestehen.

**Vorschlag, neu 2026-10-16 (Alita):** Datensatz-Uebergabe: ein Ordner je Fall unter derivatives/preprocessed, sprechende Dateinamen, alles auf der Scan-Matrix, Layout des Fremdwerkzeugs als Geschwisterordner mit dessen Namen, keine Kopien (fehlende Ordner baut ein Skript), files.xlsx mit Spaltenerklaerung, QC-Seite, Pruefsummen ([dataset-handover-one-folder-per-case-no-copies](rules/dataset-handover-one-folder-per-case-no-copies.md)). Regel 'installierbar' erweitert: JEDER Bau von 0 in neuer Umgebung mit neuem Namen.

**Nachtrag 2026-10-17 (gemessen, anderes Agentenprofil):** Der ganze README-Ablauf von `cmb_3d_unet_experiments` lief erneut von 0 (frischer Klon von GitHub, neue Umgebung, jeder Befehl woertlich): sechs Bloecke, alle gruen, 3 h 55 auf einer RTX A5000. Der Aufwand steckt in der Kreuzvalidierung selbst (2 h 28 von fuenf Trainingszuglaengen), nicht in der Installation (93 s). Lehre: README-Zeiten sind Untergrenzen, und das F1 0,963 der Bauspielzeug-Beispiele belegt nur, dass die Befehle laufen -- kein Erkennungsergebnis.

**Vorschlag, neu 2026-10-16 (Alita):** README eines Forschungspakets: eine Zeile, eine Abbildung (keine zweite, die sie wiederholt), jeder Befehl in eigenem Kopierblock mit einer Zeile Wirkung, jeder Block laeuft woertlich aus frischem Clone, Details in docs/DETAILS.md, Hardware/Software klein ganz unten; nutzt eine Kollegin schon ein anderes Werkzeug, dessen Befehle, Optionen und Ordner spiegeln ([readme-for-a-research-package](rules/readme-for-a-research-package.md)).

**Lesen bei:** Code für Messung, Prüfung, Vorbedingungen, Melder, Berichte. MCP-Server, Agenten-Werkzeuge, Skills, Testaufbau.

**Vorschlag, neu 2026-10-07 (Alita):** Ein Waechter prueft die Vorbedingung (Treiber, Karte, Netz), bevor er neu startet; scheitert sie, meldet er einmal und pausiert. 445 Neustarts in fuenf Tagen waren Taetigkeit ohne Wirkung, und ein Fehlertext, der mit einer Zahl verglichen wird, sah aus wie "noch kein Platz".

**Regel (2026-10-07):** Ein `pip freeze` ist ein Protokoll, keine Installationsdatei (Build-Kennungen wie +cu124 und %2B brechen pip sofort). Auszuliefern ist die minimale, gepinnte Liste der echten Importe; getestet ist sie erst aus einem frischen Clone in neuer Umgebung bis zum Selbsttest, Log ins Repo.

**Vorschlag, neu 2026-10-07 (Aufsicht ueber einen lokalen Agenten, neun Regeln aus neun Vorfaellen):** Jede Sperre und jede zustandsabhaengige Anweisung bekommt beim Setzen ein Verfallsereignis; Sperren an Vollstaendigkeit haengen, nicht an "zu Ende" (eine `.rc`-Sperre oeffnete fuer einen abgebrochenen Lauf, eine CPU-Anweisung ueberlebte ihren Grund um 12 Stunden, Faktor 49). Die ersten N einer sortierten Liste sind ein Block (dreimal daneben, Vollzaehlung kostete 15 s). Vor dem Probelauf eines fremden Skripts nach Schreibzielen greppen -- ein "Trockenlauf" erfuellte ein Abnahmekriterium des Beaufsichtigten. Vor der ersten Aenderung einer fremden Datei `.vor-<stempel>` anlegen. Nachlauf als `trap EXIT`, einmal ausloesen, Logzeile suchen (ein angehaengter Block hinter vier `exit` war tot). Billige Vorpruefungen ordnen, entscheiden nicht (CPU-Rangliste vom GPU-Lauf widerlegt). Vor der Deutung einer gepoolten Zahl die tragenden Faelle zaehlen (3 Faelle = 28 % aller Laesionen). Namen am Code messen ("3D-ResNet" ohne Residuen). Erst die Definition zweier Zahlen suchen, dann die Differenz deuten (zwei Zuordnungsregeln, kein Widerspruch).

**Regel (2026-10-07):** "Installierbar" heisst frische Umgebung nur mit den README-Befehlen plus Gewichte vom Release, ein CI-Job auf fremdem Runner und jede CLI-Option einmal getestet; externe Programme (FSL) brauchen ihre Umgebungsvariablen vom Paket selbst, sonst haengen sie stumm.

**Risiko, neu 2026-10-12 (Alita):** Rechenauftraege, die der Dauerlauf-Dienst startet, erben dessen MemoryHigh (32 GiB). Ein 34-GiB-Training wird gedrosselt, der Druck steigt ueber 50 %, systemd-oomd toetet die Einheit samt Schlange und Training, Restart=always wiederholt das alle 3 bis 4 Minuten: 30 Kills zwischen 11.10. 18:48 und 12.10. 09:21, kein Lauf kam durch. Bedarf wurde gegen den System-RAM geprueft, nicht gegen die eigene cgroup.

**Rules, new 2026-10-16:** (1) A Python environment on a shared machine is only isolated if you make it so: `PYTHONNOUSERSITE=1` (a user-site package shadowed the environment's), install on a compute node or as venv (conda died twice on the login node at `repodata.json`), venv fallback without `python3-venv`, check `pkg.__file__` before testing (an editable install pointed to an old clone), `rc=$?` before `$(date)`. (2) Public code knows no dataset: patterns and explicit files, BIDS as preset; dataset rules in a private script next to the data, after proving old and new give identical case lists.
